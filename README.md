# humanizer-jp — 日本語AIは、なぜ「AIっぽい」のか

同じテーマで人間とAIに記事を書かせ、**1,105本 × 2セット**を統計的に比較した。
何が「AIが書いた日本語」を見分けさせているのか。その指紋を、当てずっぽうではなく数字で特定したプロジェクトです。

- **コーパス**: 人間の記事 1,105本(Wikipedia・はてな・note・Qiita) / AI(Claude)の記事 1,105本(同じテーマで生成)
- **手法**: 形態素 n-gram の対数尤度比、文末表現の頻度分析、文埋め込み(BGE-M3, 98,328文)による意味クラスタリング、計量文体統計
- **検証**: 主要な発見はすべて、別の観点から独立に再測定して反証を試みる「査読」を通している(7観点・誇張やジャンル差・少数記事への偏りを除外)

> 対象は Claude の素のトーン。「AI一般の特徴」と「Claude固有のクセ」の切り分けは今後の課題(末尾「限界」参照)。

詳細レポート: [一般向けサマリ](docs/findings_public.md) / [検証レポート](docs/findings_verification.md) / [抽出結果の全エビデンス](docs/findings.md)

## 結論:最大の指紋は「装飾」ではなく「文のリズム」

箇条書きや太字といった見た目ではなく、**文そのものの作り方**にこそ強い特徴が出る。
最も頑健だったのは、次の一点に尽きる。

> **AIは「短く・長さのそろった文」を、読点を入れながら淡々と並べる。**

人間の文章は、長い文と短い文が混ざり、リズムに緩急がある。AIの文章は長さが驚くほど均一で、これが全特徴のなかで最も強く・最も普遍的に効く指紋だった(AI記事の **99%** が人間の平均よりも文長が均一)。

実際に並べてみると、ひと目でわかる。

**🤖 AI(Claude)が書いた文章 — どの文もほぼ同じ長さ(35〜41字)**
> なので「とにかく強い者が前に出て、力技で押し切る」みたいな展開が起きやすい。
> さらに、Zwiftには「パワーアップアイテム」というゲームっぽい要素まで存在する。
> コースの途中にあるアーチをくぐると、ランダムでアイテムがもらえるのだ。
> 「30秒間軽くなる」とか「空気抵抗を減らす」とか、まるでマリオカートである。
> 世界トップのプロ選手が、マリオカートと同じ仕組みで真剣勝負しているのだ。

**🧑 人間が書いた文章 — 長短がジェットコースターのように動く(6字→80字→7字…)**
> オセロです。
> 私はオセロが得意ではありません。
> ですが、ルフィやナルトを憑依させて「上級レベル」のコンピューターに勝つことができれば、もはやヒーローとしての素養を身に着けたと言っても良いのではないでしょうか。
> 良いですよね。
> ダメですか？

AI(🤖)の5文はどれも均整がとれている。人間(🧑)は「短い・短い・すごく長い・短い・短い」と、文の長さそのもので感情の起伏を作っている。この差が、計測上いちばんはっきり出る。

## 確定した「AIっぽさ」5つ

検証を生き残った、信頼できる特徴。上ほど強い。

### 1. 文のリズムが均一(最強の指紋)
- **文の長さがそろっている**:長さのばらつき(変動係数)はAIが人間の約3分の2。記事の99%が人間より均一。
- **一文が短く、文の数が多い**:句点「。」の密度はAIが約1.6倍。
- **どの文にも読点「、」が入る**:人間は読点ゼロの文も多いが、AIは一文に最低1つ入れる傾向。

→ 「短く整った文を機械的に積み上げる」のがAI文体の土台。

### 2. やわらかい字面(ひらがなが多い)
- ひらがなの比率がAIの方が明確に高い(約 0.48 vs 0.30)。漢字を多用して硬く書くより、**ひらがなで噛み砕く**傾向。

### 3. 特定の語彙のクセ
人間より際立って多く使う言葉がある(ジャンル差を除いても残るもの)。以下はいずれも **🤖 AIが書いた実例**:
- **「整理する」**(情報を「整理すると」とまとめたがる)
  > 🤖 主な要因を整理するとこんな感じです。
- **「〜しておきたい/〜しておきます」**(読者への配慮の前置き。人間の記事にはほぼ出ない)
  > 🤖 今回はそのやり方をいくつかメモしておきます。
  > 🤖 世の中の人がよく出してしまう NG 回答を、いくつか分析しておきたい。
- **「地味」「けれど」**(評価・逆接のクセ)
  > 🤖 replica 数の変更が PR の差分でひと目でわかるのは地味に効きます。

### 4. 談話の「型」
文章の組み立て方にもクセが出る。以下はいずれも **🤖 AIが書いた実例**:
- **「一方」「つまり」**で対比・言い換えを多用する(接続詞で論理を明示)
  > 🤖 一方、同じ規模の環境を二重で持つのでコストがかかる。
  > 🤖 つまり、これまで暗黙だったものを全部書き出すしかない、というのが出発点でした。
- **「本記事では〜」「この記事では〜」**と、自分が何を書くかを宣言する自己言及
  > 🤖 本記事ではAudioLink Ver1.2.0時点の主要関数を、目的別に日本語で解説します。

### 5. 評価でしめる定型句
- **「〜といえます」「〜といえるでしょう」「高い水準で実現されている」**など、対象を評価してまとめる締めの常套句。意味的にそっくりな言い回しが繰り返し現れる。以下はいずれも **🤖 AIが書いた実例**:
  > 🤖 ハードウェア的に減算器を別途用意しなくていいので、合理的な設計といえます。
  > 🤖 両国の友好関係を草の根レベルで支える存在として、日本人会の役割は今も大きいといえるでしょう。

## 逆に、「AIっぽさ」とは言えなかったもの

直感に反するが、**見た目の派手さは指紋にならない**ことも分かった。ここは見誤りやすいので明記する。

- **箇条書き・見出し・太字などのMarkdown装飾**
  → これは「どんな形式で出力させたか」という条件の差であって、文章そのものの性質ではない。装飾を外せば消える。**「箇条書きが多い=AI」とは言えない。**
- **丁寧さ(です・ます調)**
  → むしろ人間のブログの方が丁寧語の密度は高い。AI固有ではない。
- **漢字の多さ / 受け身**
  → 扱うジャンル(解説か・エッセイか等)で向きが変わり、AI固有の特徴とは言えない。
- **三点リーダ「…」**
  → これは**人間**の方がよく使う(余韻表現)。AIはむしろ少ない。

---

## ひとことで

> **AIっぽさは「箇条書き」ではなく「文のリズム」に宿る。**
> 短く・長さのそろった文を、読点を打ちながら淡々と並べ、「整理すると」「一方」「〜といえます」で締める——
> それが、いまのAIが書く日本語の指紋だった。

## この知見を使う:`humanize-jp` スキル

検証で確定した指紋を実用化した [Claude Code](https://claude.com/claude-code) スキルを同梱しています。
日本語文章から「AIっぽさ」を抑え、人間寄りにリライトします。

- **場所**: [`.claude/skills/humanize-jp/`](.claude/skills/humanize-jp/)
  - [`SKILL.md`](.claude/skills/humanize-jp/SKILL.md) — 効く順のリライト指針(① 文長のバラけ=最重要 → ② 句読点 → ③ tell語句の置換 → ④ 構造)+「やりすぎ厳禁」(非tellは触らない)
  - [`reference/humanize_check.py`](.claude/skills/humanize-jp/reference/humanize_check.py) — 文長CV・句点/読点密度・ひらがな率を human/AI ベンチと比較し、tell語句を検出する診断スクリプト
- **使い方**: このリポジトリで Claude Code を開き、「この文章を人間らしく直して」等と依頼すると自動的に発動します。診断だけ単体で回すことも可能:
  ```bash
  python3 .claude/skills/humanize-jp/reference/humanize_check.py 対象ファイル.md
  ```

# 調査方法(How we measured it)

ここから下は、上記の結論をどう導いたかの技術的な解説です。

## 1. 比較コーパスの作り方

「AIっぽさ」を測るには、**同じテーマを人間とAIの両方に書かせて差分を取る**のが要点です。片方だけ見ても「これはAIのクセか、それともこのジャンルの特徴か」が分かりません。

### 人間側(1,105本)
ChatGPT 一般公開(2022-11)より前=AI混入のない日本語テキストを4ソースから収集しました。

| ソース | 文体 | 本数 |
|---|---|---|
| Wikipedia 日本語版 (2021 dump) | 百科事典体(常体) | 400 |
| はてなブログ (2018–2021) | ブログ体(敬体混在) | 300 |
| Qiita (2015–2021) | 技術ブログ(敬体) | 205 |
| note (2018–2021) | エッセイ体(敬体) | 200 |

百科事典だけでなくブログを多く混ぜているのは意図的です。Wikipedia だけと比べると「百科事典 vs AIブログ」というジャンル差を「AIのクセ」と誤検出してしまうため、複数ジャンルを入れて切り分けています。

### AI側(1,105本)
人間側の各記事から **タイトル + 中立的な要約** を取り出してお題にし、同じテーマで Claude に記事を書かせました。

```
以下のテーマで日本語の記事(note / ブログ風)を書いてください。
タイトル: {title}
概要: {summary}
```

ポイントは、**「人間らしく書け」「AI臭を消せ」といったトーン指示を一切入れない**こと。素のデフォルトのトーンこそ、いま実際に世の中へ流通しているAI文体だからです。

## 2. 指紋の抽出(4つの分析)

| 観点 | 何を見るか | 手法 |
|---|---|---|
| 語彙 | 単語・連語の出現頻度差 | 形態素解析(SudachiPy)+ 対数尤度比 G²(統計的有意性)+ 効果量 |
| 文末 | 文の終わり方のクセ | 文末 n-gram の頻度比較 |
| 意味 | 言い回しが違っても同型な定型表現 | 文埋め込み(`@cf/baai/bge-m3`, 1024次元, 98,328文)+ クラスタリング |
| 計量文体 | 文長・文字種・語彙多様性・反復 | 分布比較 + Mann-Whitney U 検定 + 効果量 |

単なる頻度の差ではなく、**統計的に有意で、かつ効果量が大きいもの**だけを候補にしています。

## 3. 反証検証(ここが今回の肝)

候補が出ても、それが本当に「AIのクセ」とは限りません。次のような落とし穴があります。

- **収集条件の差**:人間側はプレーンテキストで集めたため、Markdown装飾の有無は「AIのクセ」ではなく集め方の差。
- **ジャンルの差**:解説記事とエッセイでは漢字率も違う。
- **少数記事の偏り**:特定の1〜2記事に大量に出ているだけかもしれない。
- **数値の誇張**:比較の分母を間違えると倍率が水増しされる。

そこで、抽出した指紋を **7つの観点から独立に再測定し、それぞれ別エージェントが「反証」を試みる**プロセスを通しました。結果:

| 判定 | 件数 |
|---|---|
| 確定(confirmed) | 32 |
| 弱化(weakened) | 11 |
| 収集アーティファクトへ格下げ(reclassified) | 12 |
| 完全否定(refuted) | 0 |

この検証で、当初目立っていた「Markdown装飾の多さ」などは収集条件の差と判明し、逆に**文長の均一性**が全記事の99%に効く唯一の汎用指紋として残りました。詳細は [docs/findings_verification.md](docs/findings_verification.md)。

## 4. 限界と今後

1. **単一モデル**:今回は Claude の素の文体のみ。他モデルにも共通する「AI一般の指紋」と「Claude固有のクセ」の分離は次の課題(複数モデルで同じテーマを生成して比較予定)。
2. **見た目系の公平な比較**:人間側をプレーンテキストで収集した制約上、装飾・段落構造は公平に測れていない(これらは指紋から除外)。人間側も構造を保持して再収集すれば検証可能になる。
3. **意味クラスタの感度**:言い換え系の指紋は精度は高いが対象記事数が少ない(high precision / low recall)。クラスタリング手法の感度分析が必要。

```
humanizer-jp/
├── README.md                  # 本ファイル(結論 + 調査方法)
├── .claude/skills/humanize-jp/ # 「AIらしさ」抑制スキル(Claude Code)
│   ├── SKILL.md               #   リライト指針
│   └── reference/humanize_check.py # 計量診断スクリプト
├── docs/
│   ├── findings_public.md     # 一般向けサマリ
│   ├── findings.md            # 抽出結果の全エビデンス(v1)
│   ├── findings_verification.md # 7観点の反証検証レポート
│   └── methodology.md         # 詳細手法
├── schemas/d1_schema.sql      # データスキーマ(Cloudflare D1)
├── crawler/                   # 収集 + 埋め込み生成(Cloudflare Worker)
├── scripts/analyze/           # 分析パイプライン(Python)
│   ├── loglikelihood.py       #   語彙(対数尤度比)
│   ├── sentence_endings.py    #   文末表現

└── data/analysis/             # 分析結果(JSON, エビデンス付き)
```

## 再現方法(概要)

```bash
# 1. データを D1 からローカルへ書き出す
npx wrangler d1 export humanizer-jp --remote --output data/d1_export/corpus.sql
sqlite3 data/d1_export/corpus.sqlite < data/d1_export/corpus.sql

# 2. 分析を回す(Python; sudachipy / numpy / scipy / scikit-learn / hdbscan)
python3 scripts/analyze/loglikelihood.py
python3 scripts/analyze/sentence_endings.py
python3 scripts/analyze/punctuation.py
python3 scripts/analyze/cluster_paraphrases.py
python3 scripts/analyze/extract_tells.py
```
