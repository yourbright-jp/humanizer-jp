# AI 文体特徴 (AI tells) 抽出結果サマリ

日本語コーパス比較による、Claude (Opus 系, 素のデフォルトトーン) 生成記事の文体的特徴。

- **コーパス**: human 側 (`clean_articles`) 1,105 本 / AI 側 (`ai_articles`, model=`claude`) 1,105 本
- **文埋め込み**: 98,328 文 (human 53,528 / AI 44,800) — `@cf/baai/bge-m3` (1024d)
- **採用閾値 (Phase 3)**: 対数尤度比 G² > 15.13 (p<0.0001) かつ AI 側相対頻度 ≥ 3× human 側
- **採用閾値 (Phase 4)**: クラスタサイズ ≥ 10, AI 比 ≥ 75%, lift ≥ 3×
- **生成物**: [`data/analysis/ai_tells.json`](../data/analysis/ai_tells.json) (全エビデンス付き)

> **重要な注意 (バイアス)**: human 側はプレーンテキスト (Wikipedia / ブログ本文抽出)、AI 側は
> Markdown 込みの出力。したがって Markdown 記号 (`#`, `**`, バッククォート, 箇条書き) は
> 構造的 tell として極めて強く出るが、これは「AI は Markdown を出力しがち」という性質と
> 「human コーパスがプレーン化されている」という収集上の差が混ざった結果である。
> 純粋な言語的 tell を見るときは Markdown 記号を除いた一覧 (本書後半) を参照のこと。

## 1. 文書レベル構造メトリクス (記事 1 本あたり平均)

| メトリクス | human | AI (claude) | 比 |
|---|---|---|---|
| 太字 `**…**` / 1k字 | 0.002 | 0.551 | **×368** |
| 見出し行比率 | 0.000 | 0.082 | **×206** |
| 箇条書き行比率 | 0.000 | 0.049 | **×123** |
| em dash `—` / 1k字 | 0.021 | 0.161 | ×7.8 |
| 平均段落長 (字) | 1,193 | 96 | **×0.08** |
| 段落数 | 25.2 | 32.6 | ×1.3 |
| 記事文字数 | 4,220 | 2,842 | ×0.67 |
| 三点リーダ `…` / 1k字 | 0.567 | 0.169 | ×0.30 |
| 漢字率 | 0.245 | 0.262 | ×1.1 |
| 受身率 / 1k字 | 0.631 | 0.749 | ×1.2 |

**読み取れること:**
- **強い構造化志向**: 見出し・箇条書き・太字を多用し、段落を細かく刻む (平均段落長が human の約 1/12)。「見出し → 短い段落 → 箇条書き」というブロック構造が AI 文体の最大の指紋。
- **em dash の偏愛**: `—` を human の約 8 倍使う (日本語の地の文では稀)。
- **三点リーダは逆に少ない**: human のブログ的な「…」の余韻表現は AI ではほぼ出ない。
- 1 本あたりは human より短いが段落数は多い = 短段落の積み重ね。

## 2. 語彙 tell (n-gram, Markdown 記号を除いた言語的なもの)

Markdown / 空白由来の n-gram (バッククォート, `##`, インデント, `\n\n` 等) が頻度上位を占めるが、
それらを除くと以下のような**言語的傾向**が残る。

### 単語 (1-gram)
| 語 | G² | 倍率 |
|---|---|---|
| だけ | 1266 | 3.1× |
| けれど | 551 | 13.3× |
| 少し | 472 | 3.6× |
| 整理 | 362 | 5.0× |
| 地味 | 339 | 19.4× |
| みる (〜してみる) | 332 | 3.3× |

→ 「だけ / 少し / けれど」など**緩衝・ヘッジ語**、「整理する」「〜してみる」など**メタ的な動詞**が目立つ。

### 連接 (2/3-gram) — 短段落と引用・説明フレームの痕跡
| n-gram | G² | 倍率 | 解釈 |
|---|---|---|---|
| `だ。\n\n` | 1734 | 125× | 常体 + 二重改行 (短段落の終端) |
| `た。\n\n` | 3893 | 10.6× | 同上 (過去形) |
| `ます。\n\n` | 2305 | 3.1× | 敬体 + 二重改行 |
| `、という` | 1541 | 16.8× | 引用・換言フレーム |
| `、と` | 1759 | 9.2× | 引用導入 |

→ 「一文ごとに段落を割る」癖 (`。\n\n`) が圧倒的に強い。換言・引用の `という` 系も多用。

## 3. 文末表現 tell (文末 4 文字, 上位)

| 文末 | G² | 倍率 |
|---|---|---|
| 〜ておきます | 162 | 4.4× |
| 〜ておきたい | 148 | **121×** |
| 〜ではない | 133 | 3.6× |
| 〜てほしい | 107 | 8.8× |
| 〜はずです | 105 | 5.5× |
| 〜のだろう | 97 | 8.3× |
| 〜てきます | 95 | 4.0× |
| 〜くれます | 89 | 5.8× |

→ 「(共有し)ておきたい / ておきます」のような**読者への配慮・前置き表現**、「はずです / のだろう」のような
**推量・evaluative な締め**が AI に偏る。(全 152 件は ai_tells.json 参照)

## 4. 言い換え系 tell (Phase 4 / 文埋め込みクラスタ)

surface n-gram では個別に閾値割れする「意味的に同型の定型表現」を、BGE-M3 埋め込み + HDBSCAN で捕捉。
全 98,328 文から **AI 偏向クラスタ 8 件**を抽出 (PCA 50 次元 → HDBSCAN, min_cluster_size=10)。

| # | size | AI比 | lift | パターン (代表文) |
|---|---|---|---|---|
| 1 | 32 | 0.97 | 37× | **Tips/ハマりどころ節**: 「## ハマりどころと改善 Tips」「## ハマりやすいポイント … 共有しておきます」 |
| 2 | 27 | 0.93 | 15× | **箇条書き定義列挙**: 「- **J 金融業，保険業** — …」形式の整然リスト |
| 3 | 22 | 0.95 | 25× | **伝記の枕**: 「○○という名前を知っている人は、いまではそれほど多くないかもしれません」 |
| 4 | 20 | 1.00 | — | **評価まとめ文**: 「…といえます」「表現の場を広げていきました」 |
| 6 | 11 | 1.00 | — | **高評価ヘッジ**: 「…高い水準で実現されている」「完成度が高いと評価されている」 |
| 7 | 10 | 1.00 | — | **構成予告**: 「## 全体の構成 今回構築する構成は以下のようになります」 |
| 5 | 13 | 1.00 | — | **pandas コード断片**: 「### 複数行を取得 ```python df.iloc[...]```」 |
| 8 | 11 | 0.82 | 5× | **内省的文学調**: 「何かに置いていかれているという感覚だけが、確かにあった」 |

→ n-gram では拾えない**「節レベルの定型」**が見える: ①Tips/注意点まとめ節, ②伝記の謙遜枕,
③「〜といえます」系の評価まとめ, ④構成予告。これらは Claude の**情報整理・配慮・評価**志向の現れ。

## 方法と限界

- **Phase 1-3 (頻度統計)**: SudachiPy mode C で形態素 n-gram → Dunning 対数尤度比 + 効果量フィルタ。
  実装は `scripts/analyze/{loglikelihood,sentence_endings,punctuation}.py`。
- **Phase 4 (埋め込みクラスタ)**: Workers AI `@cf/baai/bge-m3` で文埋め込み → PCA 50d → HDBSCAN(cosine)。
  実装は `crawler/src/embed.ts` (生成) + `scripts/analyze/cluster_paraphrases.py` (クラスタ)。
- **限界**:
  1. human/AI で Markdown 有無の収集差があり、構造系 tell はその差を含む (§冒頭の注意参照)。
  2. PCA 50 次元の累積寄与率は 0.403。cosine 近傍構造は概ね保たれるが、微細な言い換え差は
     取りこぼし得る。Phase 4 は「保守的に確実なクラスタのみ」を出している (noise 95%)。
  3. 単一モデル (Claude Opus 系) のみ。「AI 一般の tell」と「Claude 固有」の分離は未実施 (v2 スコープ)。
